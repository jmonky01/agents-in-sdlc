GitHub Copilot を agent mode で使うと、コードベースを調べ、変更を提案し、ファイルを編集し、コマンドを実行します。VS Code の Copilot Chat では、ツールの呼び出しやファイル編集をリアルタイムで確認できます。差分をインラインでレビューし、個々の変更を適用または取り消し、追加のプロンプトで作業を調整できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして適用します。
- セッションの途中でエージェントに指示し、ハイ コントラストに加えてライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントが、ハイ コントラスト モードを実装しています。作業中にデザイン チームから、既定のテーマが暗すぎると感じるユーザー向けのライト モードも追加してほしいと依頼されました。新しい会話を最初から始めず、既存のセッションに指示を出して作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集が順に表示されます。各ファイル編集は差分と **Keep** / **Undo** の操作とともに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取りと編集、実行を求められたターミナル コマンドが表示されます。
3. ファイル編集が提案されたら、差分を確認します。
   - **Keep** を選択して変更を適用します。
   - **Undo** を選択して変更を取り消し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開き、このセッションで変更されたファイル全体を確認することもできます。

> [!NOTE]
> ターミナル コマンドの実行などで許可が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。最後に変更内容をまとめたメッセージが表示されます。

## ライト モードを追加するようエージェントに指示する

ハイ コントラスト モードができたら、同じ会話でライト モードの切り替えを追加します。同じセッションを続けることで、エージェントは変更したコンポーネント、スタイル、local storage のパターンなどのコンテキストを保持します。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントが既存の変更を調べ、ライト モードの追加を提案する様子を確認します。
3. 新しい編集を確認し、差分ごとに **Keep** または **Undo** を選択します。
4. エージェントの方向性が希望と異なる場合（例: トグル UI を望まない方法でリファクタリングする場合）は、チャット入力欄の横にある **Stop** ボタンで停止し、追加のメッセージで意図を伝えます。

> [!TIP]
> 進行中のセッションに指示を出すと、最初からやり直すより短時間で調整できます。追加プロンプトで「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」「3 つ目のトグルを追加せず、既存の設定パネルにライト モードを統合する」「両方の切り替えにキーボード ショートカットを追加する」などと依頼できます。

## 作業セットをレビューする

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。ARIA 属性、キーボード ナビゲーション、セマンティック HTML、local storage による設定の保持など、アクセシビリティのパターンが反映されていることを確認します。
4. 問題がなければ **Source Control** パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode で進行中のセッションを監視し、各ファイル編集を確認して適用または取り消し、コンテキストを保ったまま追加プロンプトで作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を適用または取り消しました。
- 追加プロンプトで進行中のセッションに指示を出しました。

[次のレッスン][next-lesson]では、アクセシビリティ作業を PR として公開し、このラボでローカルのカスタム エージェントが作成した変更をレビューします。
